Теория 1 · Документ как дерево

HTML (HyperText Markup Language) — язык разметки. Он не считает, не принимает решений и не хранит данные. Он описывает структуру и смысл: это заголовок, это список, это ссылка, это форма. Внешний вид — задача CSS. Поведение — задача JavaScript.

Браузер читает файл сверху вниз и строит из тегов дерево. У каждого элемента есть родитель, дети и соседи. Именно поэтому говорят «DOM-дерево»: Document Object Model. 

<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8">
    <title>Экран «Сегодня»</title>
  </head>
  <body>
    <header>
      <h1>Сегодня</h1>
    </header>
    <main>
      <p>День 7 из 96.</p>
    </main>
  </body>
</html>

Схема этого документа:

дерево документа
html ├── head │ ├── meta charset │ └── title └── body ├── header │ └── h1 ← «Сегодня» └── main └── p ← «День 7 из 96»
  • Вложенность — тег внутри тега. Открывающий и закрывающий теги должны совпадать: <p>...</p>.
  • Одиночные теги — без закрывающей пары: <meta>, <img>, <br>, <input>.
  • Атрибуты — настройки в открывающем теге: <html lang="ru">, <img src="..." alt="...">.
  • Комментарии — <!-- текст -->. Браузер их не показывает, люди читают.
Браузер очень терпелив. Если забыть закрыть тег, он часто «догадается» и починит дерево сам. Но догадается по-своему. Поэтому вложенность лучше проверять сразу, а не надеяться на снисходительность браузера.

Блочные и строчные элементы. Это пока не про CSS, а про поведение по умолчанию:

  • Блочные (div, p, h1, section, ul) занимают всю ширину и начинаются с новой строки.
  • Строчные (span, a, strong, em, code) идут внутри текста, в потоке строки.

Строчный тег внутри блочного — нормально. Блочный внутри строчного — почти всегда ошибка: <a><div>...</div></a> браузер развалит.

Теория 2 · Семантические теги

Семантика — это смысл. Семантический тег сообщает, что это за часть страницы, а не как она выглядит. <div> не говорит ничего. <nav> говорит: «здесь навигация».

Ссылки и изображения:

  • <a href="plan.html">Мой план</a> — ссылка. Без href это не ссылка, а просто текст.
  • <img src="avatar.png" alt="Аватар Веры" width="48" height="48"> — картинка. alt обязателен: он читается скринридером и показывается, если картинка не загрузилась.
  • <figure> + <figcaption> — картинка или схема с подписью.

Пять правил, которые решают 90% задач:

  1. Сначала спроси: «что это по смыслу?» Потом ищи тег.
  2. Один h1 на странице. Уровни заголовков — как оглавление, а не как размер шрифта.
  3. div и span — только когда никакой другой тег не подходит.
  4. Каждый section начинается с заголовка. Иначе это просто div.
  5. Кнопка — это button, а не div с кликом. Ссылка — a. Скринридер и клавиатура это чувствуют.

Семантическая страница — как хорошо сделанная книга: обложка, оглавление, главы, подзаголовки, сноски, указатель. Можно набрать тот же текст сплошным полотном — читать будет почти невозможно.

div — это «просто страница без рубрик». Работает, но попробуй найди нужное.

Теперь посмотри на свою страницу глазами машины.

  2. F12 → вкладка Elements. Найди header, nav, main, section, aside, footer.
  3. Выдели main и открой справа вкладку Accessibility (если не видно — три точки → More tools → Accessibility).

Разбор ошибок

Прочитай фрагмент, найди проблему, потом открой ответ.

<p>Первый абзац<p>Второй абзац</p>

Первый p не закрыт. Браузер закроет его сам, но дерево может получиться не таким, как ты думала. Всегда закрывай парные теги.

<h1>Сегодня</h1> ... <h1>Задания</h1>

Два h1 на странице. Второй должен быть h2: это раздел внутри главной темы.

<div class="button">Закрыть день</div>

Это кнопка по смыслу. Нужен <button>: он работает с клавиатуры и озвучивается как кнопка.

<img src="avatar.png">

Нет alt. Скринридер прочитает имя файла или промолчит. Добавь alt="Аватар Веры". Если картинка чисто декоративная — alt="".

<ul><div>Задание 1</div></ul>

Внутри ul могут быть только li. Иначе список перестаёт быть списком для машины.

<a>Мой план</a>

Нет href. Это не ссылка: она не кликается, не фокусируется клавиатурой и не озвучивается как ссылка.

<section><p>Просто текст</p></section>

У section нет заголовка. Без заголовка это бессмысленный контейнер — используй div или добавь h2.

<body><header>...</header></body><footer>...</footer>

footer оказался вне body — это ошибка вложенности. Всё видимое содержимое живёт внутри body.

Проверь себя

HTML — язык программирования?

Нет. Это язык разметки: он описывает структуру и смысл, но не содержит вычислений и логики.

Зачем нужна семантика, если CSS всё равно делает красоту?

Семантика нужна машинам и людям: скринридерам, поисковикам, клавиатуре, будущей тебе. CSS меняет вид, но не смысл.

Чем <section> отличается от <div>?

section — смысловой раздел с заголовком. div — нейтральный контейнер без смысла.

Почему <h1> должен быть один?

Это главная тема страницы. Несколько h1 ломают оглавление для скринридера и поисковика.

Что делает атрибут alt?

Описывает картинку текстом: для скринридера, для случая, когда картинка не загрузилась, и для поиска. Декоративная картинка получает пустой alt="".

Чем блочный элемент отличается от строчного?

Блочный занимает всю ширину и начинается с новой строки. Строчный идёт внутри текста. Это поведение по умолчанию, CSS может его изменить.

Можно ли вкладывать div в a?

Технически браузер починит, но по стандарту HTML5 ссылка может содержать блочные элементы. Надёжнее — ссылка внутри блока или display:block у ссылки. Главное — не строчный тег вокруг блочного.

Что такое DOM?

Дерево элементов, которое браузер построил из HTML. Через DOM JavaScript меняет страницу.

Почему кнопку нельзя делать из div?

div не имеет роли кнопки: не фокусируется клавиатурой, не реагирует на Enter и пробел, не озвучивается как кнопка. button даёт всё это бесплатно.

Что важнее: правильные теги или красивый вид?

Сначала правильные теги, потом вид. Красоту можно переделать за час, кривую структуру — за дни.

Теория 1 · Анатомия формы

Форма — контейнер для полей ввода и кнопок. Она умеет собирать значения и отправлять их на сервер. Даже если сервера пока нет, форма полезна: браузер проверяет данные, клавиатура работает, а значения можно прочитать. 

<form action="/save" method="post">
  <label for="date">Дата</label>
  <input id="date" name="date" type="date" required>

  <button type="submit">Сохранить</button>
</form>

Разберём каждую часть:

  • action — адрес, куда уйдут данные. Пока можно поставить # или оставить пустым.
  • method — как отправлять: get (данные в адресной строке) или post (в теле запроса). Пароли и личные данные — только post.
  • name — имя поля для сервера. Без name значение не отправится вообще.
  • id — имя поля для страницы. По нему label связывается с полем.
  • label — подпись. Клик по ней ставит курсор в поле. Скринридер читает её как название поля.
  • required — поле обязательно. Браузер не даст отправить пустым.
  • placeholder — серая подсказка внутри поля. Исчезает при вводе. Не заменяет label.
Главная пара дня: label for="date" + input id="date". Если for и id не совпадают, подпись не связана с полем. Клик не работает, скринридер молчит. Это ошибка №1 в формах.

Если вопрос оторван от строки, человек не знает, что писать. Если for не совпал с id, с формой происходит то же самое.

Теория 2 · Выбор, валидация и доступность

Radio или checkbox? Правило простое:

  • radio — «выбери одно из»: настроение, тариф, пол. У всех radio одной группы одинаковый name.
  • checkbox — «отметь всё, что подходит»: теги, согласия, выполненные задания. У каждого свой name (или общий массив на сервере).
<fieldset>
  <legend>Настроение</legend>

  <label><input type="radio" name="mood" value="ok"> норм</label>
  <label><input type="radio" name="mood" value="tired"> устала</label>
  <label><input type="radio" name="mood" value="great"> отлично</label>
</fieldset>

fieldset + legend — рамка и название группы. Это не украшение: скринридер прочитает «Настроение, группа» и пользователь поймёт контекст.

Выпадающий список и большой текст:

<label for="week">Неделя</label>
<select id="week" name="week">
  <option value="1">Неделя 1</option>
  <option value="2" selected>Неделя 2</option>
</select>

<label for="note">Что поняла</label>
<textarea id="note" name="note" rows="4"></textarea>

Кнопки: button по умолчанию имеет type="submit" — отправляет форму. Если кнопка внутри формы не должна отправлять, пиши type="button". type="reset" очищает поля, но этим почти никто не пользуется: случайное нажатие стирает введённое.

Валидация браузером — бесплатная проверка до отправки:

  • required — не пусто;
  • type="email" — похоже на почту;
  • minlength="10" — не короче 10 символов;
  • min="0" max="5" — число в диапазоне;
  • pattern="[0-9]{4}" — ровно четыре цифры.

CSS-состояния помогают показать проблему: :valid, :invalid, :focus, :required. Но цвет — не единственный сигнал: добавь текст.

Доступность формы — это не про «слабых». Кто-то открывает сайт с телефона одной рукой, кто-то с клавиатуры, кто-то с экранным диктором. Связанный label, понятные сообщения и порядок Tab делают форму удобной для всех.
ловушкаplaceholder вместо label

Подсказка исчезает, как только человек начал печатать. Он забывает, что это было за поле. Скринридер может не прочитать placeholder. Всегда делай видимый label, а placeholder — только примером формата.

Нажми Tab и иди по форме. Видно ли, где ты находишься? Если фокус не виден — добавь :focus-visible стиль. Если Tab перескакивает через поле — там div вместо input или отрицательный tabindex.

Мини-задание · что не так с формой

<input type="text" placeholder="Имя">

Нет label и нет name. Placeholder исчезнет, а на сервер ничего не уйдёт.

<label for="email">Почта</label><input id="mail" type="email">

for="email" не совпадает с id="mail". Подпись не связана с полем.

Три radio с разными name

Они не образуют группу: можно выбрать все три одновременно. У radio одной группы должен быть одинаковый name.

<input type="number" min="0" max="5"> без label

Непонятно, что вводить: часы? оценки? Нужен видимый label.

<button>Отмена</button> внутри формы

По умолчанию это submit: кнопка отправит форму. Для отмены нужен type="button".

<textarea>Текст</textarea> с текстом внутри

Текст между тегами станет значением поля. Обычно так делать не надо: используй placeholder или пустое поле с label.

<input type="checkbox" name="mood"> норм и ещё два таких же

Для выбора одного варианта нужны radio, а не checkbox. Checkbox — независимые галочки.

<form method="get"> с полем пароля

Пароль попадёт в адресную строку и историю. Для паролей — только method="post" и HTTPS.

Проверь себя

Зачем полю name?

Это имя, под которым значение уйдёт на сервер. Без name поле не отправляется.

Зачем полю id и как он связан с label?

id — уникальное имя элемента на странице. label for="..." ссылается на этот id, и клик по подписи активирует поле.

Чем placeholder отличается от label?

label — постоянная подпись, видна всегда. placeholder — временная подсказка внутри поля, исчезает при вводе.

Radio и checkbox — в чём разница?

Radio — выбор одного варианта из группы (одинаковый name). Checkbox — независимые галочки, можно выбрать несколько.

Что делает required?

Запрещает отправку формы, пока поле пустое. Браузер показывает сообщение и подсвечивает поле.

Что делает fieldset?

Группирует связанные поля и даёт группе название через legend. Помогает скринридерам и логике.

Почему у кнопки важен type?

По умолчанию кнопка внутри формы — submit. Если нужна другая роль, укажи type="button", иначе она отправит форму.

Что такое валидация браузером?

Встроенная проверка полей по атрибутам: required, type, minlength, pattern. Работает без JavaScript.

Почему пароль нельзя отправлять методом GET?

Данные GET попадают в адресную строку, историю и логи. Пароль должен идти в теле POST-запроса по HTTPS.

Как проверить форму без мыши?

Пройди Tab, Shift+Tab, Space, стрелками. Все поля должны быть достижимы, фокус — виден, подписи — читаемы.

Теория 1 · Подключение и селекторы

Три способа подключить CSS. В проекте используем первый:

  1. Внешний файл — <link rel="stylesheet" href="style.css"> в head. Главный способ: стили переиспользуются, кэшируются, не мешают разметке.
  2. Внутри документа — <style>...</style>. Годится для быстрых экспериментов и одной страницы.
  3. Внутри тега — style="color: red". Самый сильный и самый вредный: не переиспользуется, засоряет HTML, побеждает почти всё.

Правило CSS состоит из селектора и блока объявлений:

/* селектор */  /* свойство: значение; */
h1            { color: #b6ff3c; font-size: 32px; }

.note         { color: #9aa7c7; }

#intro        { border-left: 3px solid #6c8cff; }

Селекторы — это язык, на котором ты говоришь «к кому применить»:

  • :hover — курсор над элементом;

  • :active — момент нажатия;
  • :first-child, :last-child, :nth-child(2n) — положение среди соседей;
  • :not(.done) — все, кроме указанных;
  • :checked, :disabled, :required, :valid, :invalid — состояние формы.

Теория 2 · Каскад и специфичность

Каскад — набор правил, по которым браузер решает, какое объявление применить, если их несколько. Порядок такой:

  1. Важность и происхождение: стили браузера → стили пользователя → твои стили. !important переворачивает порядок и побеждает автора.
  2. Специфичность: чем «точнее» селектор, тем он сильнее.
  3. Порядок: при равной специфичности побеждает то, что написано ниже.
  4. Наследование: если свойства нет ни в одном правиле, элемент может взять его у родителя.

Специфичность записывают четырьмя числами: (inline, id, class, tag).

ЧтоВесПример
inline style1,0,0,0style="color:red"
id0,1,0,0#intro
class, атрибут, псевдокласс0,0,1,0.note, [type], :hover
тег, псевдоэлемент0,0,0,1p, ::before

Примеры:

  • p → 0,0,0,1
  • .note → 0,0,1,0
  • nav a:hover → 0,0,1,2 (класс :hover + два тега)
  • #intro .note a → 0,1,1,1
  • a[href^="https"] → 0,0,1,1
  • ul li::before → 0,0,0,3

Сравнение идёт слева направо: один id сильнее ста классов. Поэтому «добавлю ещё один класс» не всегда помогает — иногда нужно убрать id или !important из чужого правила.

Наследование. Наследуются в основном текстовые свойства: color, font-family, font-size, line-height, text-align. Не наследуются: margin, padding, border, display, width, background. Поэтому body { color: ... } работает, а body { margin: ... } не размножается на детей.

!important — красная кнопка. Она есть, но пользоваться ей стоит, когда ты чинишь чужой код и не можешь его менять. В своём проекте !important почти всегда означает, что структура селекторов запуталась.

Каскад — как иерархия законов: конституция важнее указа, указ важнее инструкции. Специфичность — как вес на весах: id — гиря, класс — гантеля, тег — монета. Если вес равный, побеждает тот, кто встал позже.

Разбор ошибок

h1 { color: red } не применяется

Проверь: подключён ли style.css, нет ли опечатки в пути, не перебито ли правило более сильным селектором. Ctrl + F5 сбрасывает кэш.

.note { ... } не работает, хотя класс есть

В HTML класс написан как class="note " с пробелом или class="Note" с большой буквы. CSS чувствителен к регистру в классах.

#intro { color: blue } перебивает .note { color: red }

Так и должно быть: id сильнее класса. Если нужен красный — повысь класс или убери id из стилей.

Стиль из style="..." не перебивается

Inline-стиль имеет вес 1,0,0,0. Убрать его из HTML — правильное решение. !important — крайняя мера.

Два правила одинаковой специфичности, применяется не то

Побеждает то, что ниже в файле (или в более поздно подключённом файле). Порядок — часть каскада.

body { margin: 0 }, а у детей отступы остались

margin не наследуется. Нужно задать его конкретным элементам или использовать сброс.

a:hover { ... } не работает на телефоне

На сенсорном экране нет наведения. Состояние должно быть доступно и через :focus-visible, а информация — не только в hover-эффекте.

После добавления * { ... } всё поехало

Универсальный селектор применяется ко всем элементам, включая служебные. Используй точечно или сбрасывай только нужное.

Проверь себя

Что такое каскад?

Правила, по которым браузер выбирает победившее объявление: важность, специфичность, порядок, наследование.

Как считается специфичность?

Четырьмя числами: inline, id, class/атрибут/псевдокласс, тег/псевдоэлемент. Сравнение слева направо.

Что сильнее: #id или десять классов?

#id: один id в третьей позиции сильнее любого количества классов.

Что наследуется, а что нет?

Наследуются текстовые свойства (цвет, шрифт, межстрочный интервал). Не наследуются отступы, рамки, размеры, display.

Зачем нужен :focus-visible?

Показывает фокус при навигации клавиатурой, но не мигает при клике мышью. Важно для доступности.

Чем ::before отличается от :hover?

::before — псевдоэлемент, создаёт виртуальную часть. :hover — псевдокласс, состояние.

Почему !important считается плохой практикой?

Он ломает естественный каскад: следующие правила не могут перебить, и стили становятся неуправляемыми.

Что делает nav > a?

Выбирает только прямых детей nav — ссылки первого уровня, не вложенные в другие элементы.

Где посмотреть итоговое значение свойства?

DevTools → Elements → Computed. Там же видно, какое правило его задало.

Почему классы лучше id для стилей?

Класс переиспользуется, не создаёт лишней специфичности, его можно комбинировать. Id уникален и слишком «тяжёлый».

Теория 1 · Четыре слоя коробки

Каждый элемент — прямоугольник, у которого есть четыре зоны, от центра к краю:

  1. content — содержимое: текст, картинка, вложенные элементы.
  2. padding — внутренний отступ, «пузырчатка» вокруг содержимого. Входит в фон элемента.
  3. border — рамка между padding и margin.
  4. margin — внешний отступ, расстояние до соседей. Не входит в фон, не кликается.

По умолчанию box-sizing: content-box: заданная width — это только content. Итоговая ширина:

итоговая ширина = width + padding-left + padding-right
                + border-left + border-right

300 + 16 + 16 + 1 + 1 = 334 px

Это и есть главный сюрприз новичка: «я же сказала 300». Решение — box-sizing: border-box:

*, *::before, *::after {
  box-sizing: border-box;
}

.card {
  width: 300px;   /* теперь это итоговая ширина */
  padding: 16px;  /* входит внутрь */
  border: 1px solid #2a3550;
}

margin в размер элемента не входит — он снаружи. Поэтому карточка с width: 300px и margin: 20px занимает 300 пикселей, но между ней и соседом будет 20 (или больше, если сосед тоже с margin — см. ниже).

Схлопывание margin (margin collapse). Вертикальные отступы соседних блоков не складываются, а «схлопываются» в больший:

.a { margin-bottom: 30px; }
.b { margin-top: 20px; }

/* расстояние между ними — 30px, а не 50px */

Это не баг, а правило потока. Горизонтальные margin так себя не ведут. Схлопывание не работает у flex- и grid-контейнеров — ещё одна причина любить flex.

Полезные приёмы:

  • margin: 0 auto — центрировать блочный элемент с заданной шириной.
  • margin: 0 у body — убрать стандартные 8 пикселей браузера.
  • padding — когда нужен фон вокруг содержимого; margin — когда нужно расстояние до соседа.
  • Отрицательный margin сдвигает элемент, но им легко сломать раскладку. Пока не используй.

content-box — «300 мм — это размер товара». border-box — «300 мм — это габарит коробки». Второе удобнее, когда коробки должны стоять ровно.

Единицы:

  • px — фиксированные пиксели. Хорошо для рамок и мелких деталей.
  • % — процент от родителя. Ширина — от ширины родителя, высота — от высоты (часто не работает, если высота не задана).
  • rem — от размера шрифта корня (html). Удобно для масштабирования.
  • em — от размера шрифта текущего элемента. Коварно при вложенности.
  • vh / vw — процент от высоты/ширины окна. 100vh на мобильных может учитывать адресную строку — есть dvh.
  • ch — ширина символа «0». Удобно для текстовых колонок.

line-height лучше задавать без единиц: line-height: 1.6 — это множитель от размера шрифта, он наследуется корректно.

Декор:

  • border-radius — скругление углов;
  • box-shadow — тень: смещение по X, по Y, размытие, цвет;
  • outline — внешний контур, не влияет на размеры. Идеален для фокуса;
  • background — цвет, градиент или картинка.

max-width важнее width для адаптивности: max-width: 900px; width: 100% — блок не вылезет за экран.

  outline-offset: 2px;

Добавь внутрь карточки кнопку и проверь: при переходе Tab на кнопку карточка получает рамку.

Разбор ошибок

Карточка шириной 300 px занимает 332 px

Стандартный content-box: 300 + padding 16×2 + border 1×2 = 334. Добавь box-sizing: border-box.

Два блока с margin 20 и 30, а расстояние 30

Вертикальные margin схлопываются: берётся больший. Это нормальное поведение, не баг.

margin: 0 auto не центрирует

У элемента нет ширины (блок занимает 100%) или он inline. Задай width/max-width и display: block.

Текст вылезает за карточку

Нет overflow или min-width: 0 во flex-контейнере. Для длинных слов — overflow-wrap: anywhere.

Высота 100% не работает

У родителя не задана высота. Проценты считаются от конкретного значения, а не от «сколько получится».

На телефоне блок шире экрана

Фиксированная width: 360px при экране 320. Используй max-width: 360px; width: 100%.

Тень обрезается

У родителя overflow: hidden. Тень рисуется за границами элемента и обрезается вместе с ними.

Отступы «прыгают» при наведении

В :hover изменён border-width или padding. Меняй цвет рамки, а не толщину, либо компенсируй размер.

Проверь себя

Из каких четырёх слоёв состоит коробка?

content, padding, border, margin — от центра к краю.

Что делает box-sizing: border-box?

Включает padding и border в заданную ширину/высоту. Итоговый размер остаётся равным width.

Чем padding отличается от margin?

Padding — внутри, вокруг содержимого, входит в фон и кликабельную область. Margin — снаружи, расстояние до соседей.

Что такое схлопывание margin?

Вертикальные отступы соседних блоков не складываются, а выбирается больший.

Почему margin: 0 auto центрирует?

Автоматические боковые отступы делят свободное место поровну. Нужна заданная ширина.

Чем outline отличается от border?

Outline не занимает места и не влияет на размеры/раскладку. Поэтому хорош для фокуса.

Когда padding, а когда margin?

Padding — если нужен фон/клик вокруг содержимого. Margin — если нужно расстояние до другого элемента.

Почему max-width лучше фиксированной width?

Блок адаптируется к узкому экрану, но не растягивается бесконечно на широком.

Что делает display: none?

Полностью убирает элемент из раскладки: он не занимает место и не показывается.

Почему line-height: 1.6 лучше line-height: 26px?

Множитель наследуется корректно и масштабируется вместе с размером шрифта. Фиксированные пиксели ломаются при смене размера.

Теория 1 · Оси и свойства

display: flex вешается на контейнер. Его прямые дети становятся flex-элементами и выстраиваются вдоль оси.

  • Главная ось (main axis) — направление, в котором выстраиваются элементы. По умолчанию слева направо.
  • Поперечная ось (cross axis) — перпендикулярно главной.

Свойства контейнера:

СвойствоЧто делаетЗначения
flex-directionзадаёт главную осьrow, row-reverse, column, column-reverse
justify-contentраспределяет вдоль главной осиflex-start, center, flex-end, space-between, space-around, space-evenly
align-itemsвыравнивает вдоль поперечнойstretch, flex-start, center, flex-end, baseline
flex-wrapразрешает переносnowrap, wrap, wrap-reverse
gapпромежутки между элементамилюбая длина: 8px, 1rem
align-contentвыравнивает строки при wrapкак justify-content

Свойства элементов:

  • flex-grow — сколько свободного места забрать (0 — не расти);
  • flex-shrink — можно ли сжиматься;
  • flex-basis — исходный размер до распределения;
  • flex: 1 — сокращение: 1 1 0% («займи всё свободное место»);
  • align-self — переопределить выравнивание для одного элемента;
  • order — изменить визуальный порядок (осторожно с доступностью).
.row {
  display: flex;
  gap: 12px;
  justify-content: space-between;
  align-items: center;
  flex-wrap: wrap;
}

.row__main { flex: 1; min-width: 0; }
min-width: 0 — спасательный круг. Flex-элемент по умолчанию не сжимается меньше своего содержимого. Длинный текст или картинка могут вылезти. min-width: 0 разрешает сжатие, и тогда работает overflow: hidden / text-overflow.
из другой областиПолка с книгами

flex-direction — как стоит полка: горизонтально или вертикально. justify-content — как расставить книги вдоль полки: слева, по центру, по краям, с равными промежутками. align-items — как выровнять книги по высоте: по верхнему краю, по центру, по нижнему.

ловушкаПутать justify-content и align-items

Запомни привязку к оси: justify-* — всегда главная ось, align-* — всегда поперечная. Если поменяла flex-direction на column, оси поменялись местами — и свойства тоже.

Теория 2 · Пять паттернов

Эти пять конструкций покрывают большинство интерфейсов. Выучи их руками, не копипастом.

1. Навбар: логотип слева, меню справа.

.topbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 16px;
  padding: 12px 20px;
}

2. Центрирование по обеим осям.

.center {
  display: flex;
  align-items: center;
  justify-content: center;
  min-height: 240px;
}

3. Карточки в ряд с переносом.

.cards {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}

.cards > * {
  flex: 1 1 240px; /* минимум 240, остальное делится */
}

4. Сайдбар и контент.

.layout {
  display: flex;
  gap: 24px;
  align-items: flex-start;
}

.layout__side { flex: 0 0 220px; }
.layout__main { flex: 1; min-width: 0; }

5. Прижатый футер.

body {
  min-height: 100dvh;
  display: flex;
  flex-direction: column;
}

main { flex: 1; } /* забирает всё свободное место */
footer { margin-top: auto; }

Flex или grid? Flex — про одно направление (ряд или колонка). Grid — про сетку из строк и столбцов одновременно. Если тебе нужно «две колонки и три ряда» — это grid, он будет на следующей неделе. Если «элементы в ряд с промежутками» — flex.

приём профиgap вместо margin

Не расставляй margin-right каждому элементу и не убирай его у последнего. gap делает ровные промежутки и не создаёт «хвост» после последнего элемента. Работает во flex и grid.

ловушкаflex: 1 без min-width

Колонка с длинным словом или таблицей откажется сжиматься и выломает раскладку. Добавь min-width: 0 и overflow-wrap: anywhere, если текст может быть длинным.

Разбор ошибок

Элементы не выстраиваются в ряд

display: flex повешен не на контейнер, а на сам элемент, или у контейнера display: block перебивает.

justify-content не работает

Возможно, главная ось вертикальная (flex-direction: column) — тогда justify-content двигает по вертикали, а горизонталь — align-items.

gap не даёт эффекта

У контейнера нет display: flex/grid, или gap написан на элементе, а не на контейнере.

Карточки не переносятся

Забыт flex-wrap: wrap. По умолчанию nowrap, и элементы сжимаются.

Текст вылезает из колонки

Нужен min-width: 0 у flex-элемента и, при необходимости, overflow-wrap: anywhere.

Высота элементов разная, хотя align-items: center

Проверь, не задана ли высота у детей, и не мешает ли align-self.

Футер не прижат к низу

У body нет min-height: 100dvh и display: flex; flex-direction: column, либо у main нет flex: 1.

На телефоне горизонтальная прокрутка

Где-то фиксированная ширина больше экрана или отрицательный margin. Проверь width: 100%, max-width и min-width: 0.

Проверь себя

Что такое главная и поперечная ось?

Главная задаётся flex-direction (по умолчанию горизонтальная). Поперечная перпендикулярна ей.

Чем justify-content отличается от align-items?

justify-content распределяет вдоль главной оси, align-items выравнивает вдоль поперечной.

Что делает flex-wrap: wrap?

Разрешает перенос элементов на новую строку, когда не хватает места.

Что означает flex: 1?

Сокращение flex: 1 1 0%: элемент может расти и сжиматься, исходная база — ноль, свободное место делится.

Зачем gap, если есть margin?

gap даёт ровные промежутки без «хвоста» после последнего элемента и не схлопывается.

Зачем min-width: 0?

Разрешает flex-элементу сжиматься меньше содержимого, чтобы длинный текст не ломал раскладку.

Как прижать футер к низу?

body — flex-колонка с min-height: 100dvh, main — flex: 1.

Чем flex отличается от grid?

Flex — одно направление, grid — строки и столбцы одновременно.

Что делает align-self?

Переопределяет align-items для одного конкретного элемента.

Почему order стоит использовать осторожно?

Он меняет визуальный порядок, но не порядок в DOM. Клавиатура и скринридер пойдут по исходному порядку — можно запутать пользователя.

Чего приложение не меняет

Самый опасный миф: «в приложении можно не разбираться в терминале, Git и путях». Можно не печатать команды. Разбираться всё равно придётся — иначе нечем проверить, что сделал агент.

  • Модель — та же. Качество ответа зависит от контекста и задачи, а не от окна.
  • Разрешения — те же. Подтверждение кнопкой не делает опасную команду безопасной.
  • Файлы — те же. Приложение не хранит «свою» копию проекта.
  • Git — тот же. Коммит, push и откат остаются коммитом, push и откатом.
  • Ошибки — те же. Красный текст в консоли никуда не исчезает, просто его виднее.

Читать диффы, смотреть несколько файлов, проверять HTML в превью, вести несколько сессий, работать с длинными путями. На Windows это особенно заметно: не нужно вспоминать про cd /d, кавычки и диск.

Windows-детали, которые ломают новичков

1. cd /d — это команда cmd, а не PowerShell. В PowerShell флаг /d не нужен, и та же строка сработает иначе:

:: cmd — можно менять диск
cd /d "C:\Users\Vera\OneDrive\Документы\vb_ed"
# PowerShell — просто cd, без /d
cd "C:\Users\Vera\OneDrive\Документы\vb_ed"

Проверить, где ты: pwd в PowerShell или cd без аргументов в cmd. В приложении это не нужно — папка выбирается мышью.

2. Пробелы и кириллица в пути. Путь C:\Users\Vera\OneDrive\Документы\vb_ed содержит и то, и другое. В терминале всегда бери его в кавычки. В приложении просто выбери папку — путь подставится сам.

3. Установка. Приложение для Windows — обычный установщик .exe (x64 или ARM64). CLI на Windows не ставится через пакетные менеджеры: нужен отдельный архив с бинарником. Если команда opencode не находится — либо бинарник не в PATH, либо проще запустить приложение.

4. Два окна — один проект. Если терминал и приложение открыты в одной папке, они видят одни файлы. Не запускай две задачи, которые одновременно правят один и тот же файл: агенты не согласуют правки между собой.

Не путай: «приложение для Windows» — это не WSL и не отдельная операционная система. Это тот же OpenCode с графическим интерфейсом. WSL понадобится только для инструментов, которых нет под Windows, — для HTML и CSS он не нужен.

Проверь себя · терминал и приложение

Терминал и приложение — это две разные программы с разными сессиями?

Нет. По умолчанию это два клиента к одному фоновому сервису. Сессии, конфигурация и разрешения общие.

Если работать в приложении, Git можно не учить?

Нет. Git остаётся Git: коммиты, push и откаты делает тот же инструмент. Приложение меняет интерфейс, а не модель работы.

Почему cd /d "D:\codex" может не сработать?

Это синтаксис cmd. В PowerShell флаг /d не используется — там достаточно cd "D:\codex".

В терминале — git diff и git status. В приложении — панель просмотра изменений. Смысл один: сначала прочитать, потом коммитить.

Что делать, если агент просит разрешение на непонятную команду?

Не подтверждать. Спросить, что команда делает и что изменится на диске. Это правило не зависит от интерфейса.
